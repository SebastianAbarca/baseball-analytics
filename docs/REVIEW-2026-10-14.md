The repairs materially improve the project, but the previous review is not fully closed. Contact suppression, spray direction, regular-season scope, and team-stint attribution now have supporting code and local-data evidence. Spin and cache handling are substantially better. ## Highest-priority findings

### 1. P1 — Sprint-speed percentiles still become feet per second

Newly confirmed in this sweep; this is not a claim that the latest commit introduced the defect.

[_savant_batting_aggregate](../baseball_construction/modules/ingest.py#L459) merges the percentile-rank endpoint into the batting data. Its `sprint_speed` is a percentile. [_sanitize_sprint_speed](../baseball_construction/modules/ingest.py#L574) only removes numbers outside 20–32; it does not establish the unit. Percentiles 20–32 survive as plausible running speeds, while faster runners' higher percentile numbers are removed.

Concrete saved result: Juan Soto's 2022 SD and WSH portraits store `sprint_speed_raw=32.0` and award `elite speed`. Savant reports **26.6 ft/s and percentile 32**. The code is treating the percentile as the physical measurement. [Savant player record](https://baseballsavant.mlb.com/savant-player/juan-soto-665742?season=2023).

Across the current qualified hitter portraits, there are 6,165 distinct player-seasons, only 810 with non-null speed, and every retained speed is an integer. There are 268 `elite speed`, 67 `fast`, and 72 `station-to-station` firings across team rows. These counts describe the affected pathway, not independently verified errors for every individual row. The source trace and Soto example establish the bug without relying on that distribution alone.

**Required repair:** load actual ft/s from the sprint-speed leaderboard and join by MLBAM ID. Store the raw measurement and percentile separately. Rebuild the database/root caches, frozen era, portraits, projections, and serving artifacts that consume speed. A range check alone cannot repair units. Add an independent reference check that would reject Soto's 32 ft/s.

### 2. P1 — Build failure still does not prevent publication

Original finding 12 remains open. [refresh.main](../baseball_construction/scripts/refresh.py#L742) discards the portrait-stage failure count and eventually returns zero. [stage_publish](../baseball_construction/scripts/refresh.py#L659) continues into league and Scout publication after portrait refusal. [nightly](../baseball_construction/scripts/nightly.py#L219) records build problems but publishes before acting on them.

Reproductions:

- Two simulated portrait failures: refresh still called publishing and exited **0**.
- One refused portrait: refresh's publish stage and the standalone publish CLI still called both league and Scout publication.
- Two simulated nightly portrait failures: nightly called publishing, then exited **1**. The failure status arrives after the writes would have happened.

**Required repair:** validate the complete candidate before the first write and propagate failure immediately. Apply the check to every publishing entry point. Versioned releases with one activation step would also prevent readers seeing mixed generations after a mid-publication failure.

### 3. P1 — Scoped publishing can still delete unrelated Scout seasons

Original finding 13 remains open. Nightly passes a season scope, but [the general publish CLI](../baseball_construction/scripts/publish.py#L442) and [refresh](../baseball_construction/scripts/refresh.py#L661) do not pass it to Scout. [publish_scout](../baseball_construction/scripts/publish.py#L365) treats published rows absent from local inputs as deletions. No complete 30-team preflight protects even the scoped path.

A fake-client reproduction with an empty local player collection issued a deletion for an existing 2024 Scout row. Calling the general CLI with `--seasons 2025` still invoked Scout without a scope.

**Required repair:** pass the requested scope through every artifact, require all expected portraits in each replacement season, and reject missing/corrupt input before writing or deleting anything. Preserve unrelated seasons.

### 4. P1 — Expanded fingerprints still allow stale inputs to look current

Original finding 14 is partially addressed: all six league caches and rank-direction maps now participate. The remaining holes are consequential:

- [_gate_digest](../baseball_construction/modules/team_portrait.py#L2560) hashes selected public constants, not function implementations or underscore-prefixed constants. Replacing the trait builder with one returning no tags left the gate fingerprint unchanged.
- [portrait_is_current](../baseball_construction/modules/team_portrait.py#L2627) still accepts a current-schema portrait with no build fingerprint.
- [rederive_traits](../baseball_construction/scripts/rederive_traits.py#L188) stamps current provenance onto previously stored feature inputs. A copied portrait marked with an old source fingerprint became “current” after replay, without recomputing its source features.
- Raw Statcast, database player snapshots, and several external feeds still lack complete source identity in the fingerprint.

All 360 current local portraits pass the existing predicate. That is useful consistency evidence, but the reproductions show it is not proof of current data and logic.

**Required repair:** separate source/feature identity from trait-definition identity; include the actual implementation version and relevant source snapshots. Trait-only replay must preserve feature provenance and refuse incompatible inputs. Reject missing provenance after migration.

## Other confirmed open defects

### P2 — Pitch outcomes and tunnel adjacency remain inconsistent

Original finding 10 remains open. [pitch_mix](../baseball_construction/modules/pitch_mix.py#L148) and its discipline loader count foul tips as whiffs; `pitch_aggregates` treats them as contact. `whiff_pct` also means whiffs per pitch in one path and per swing in another. A temporary-cache test containing 150 foul tips and no swinging misses produced `whiff_pct=1.0` and `csw_pct=1.0` in pitch mix.

[build_pitch_pairs](../baseball_construction/modules/tunneling.py#L208) checks same at-bat but not adjacent pitch numbers. A three-pitch example with an untracked middle pitch still produced a pair between pitches 1 and 3. Refresh explicitly preserves the old filtering behavior; rebuilding the cache does not correct its semantics.

**Repair:** share outcome definitions, distinguish whiffs per swing from swinging strikes per pitch, and require a pitch-number difference of one before pairing. Rebuild the affected pools and tags.

### P2 — Steal-attempt ranks remain teammate-relative

Original finding 9 remains open. [The rank calculation](../baseball_construction/modules/team_portrait.py#L1070) still operates on `team_bat`. The new season-total denominator is appropriate, but the reference population is unchanged.

The saved portraits contain **241 distinct player-seasons with different attempt-rate percentiles across teams**. For example, Ben Zobrist 2015 has the same 3 SB, 3 CS, and 535 season PA on both rows, but ranks 33.3 on ATH and 20.0 on KC.

**Repair:** compute one eligible league-wide runner population per season and reuse its rank across team stints. Decide explicitly how zero/one-attempt players are represented.

### P2 — Compare keys still omit hitter/pitcher identity

Original finding 15 remains open. [scout_rows and scout_comps](../baseball_construction/schema_serving.sql#L264) still identify targets as `player_id|team|season`; the later row wins when a hitter and pitcher share that key. The local portraits contain **348 player/team/season keys represented on both sides**. This includes historical pitchers with batting records, not just designated two-way stars.

**Repair:** carry `grp` or an equivalent side identifier through option values, lookups, and comparison targets. Also prevent another team-stint copy of the target player-season from becoming an artificial perfect comparison.

### P2 — Service time still subtracts injured-list days

Original finding 11 remains open. [The estimator](../baseball_construction/modules/database.py#L578) still subtracts IL days. MLB service accrues on the major-league injured list. [MLB definition](https://www.mlb.com/glossary/transactions/service-time).

The debut-to-season approximation also does not reconstruct roster membership, and the 2020 branch does not establish that the player actually occupied a roster. These code findings do not establish the size of the error in the deployed UI.

**Repair:** use a service ledger/transaction intervals, or relabel this as a tenure proxy and remove contractual interpretations. The current V10 assumptions would not establish correctness of the service ledger.

## Methodology and documentation still needing attention

- Framing remains a broad-zone called-strike proxy without full pitch-location/count/umpire adjustment. `scripts/battery_base.py` still fails to import because `_FR_TOP` was removed; that failure was reproduced.
- Deployment “leverage” remains absolute realized win-expectancy change, not a pre-outcome opportunity measure. New stint accounting does not change that distinction.
- The saved projected profile remains retrospective and calls `build_hitter_traits` without PA. NYY and LAD 2025 projected hitter trait densities still contain only `elite speed`, now additionally exposed to the speed-unit problem above.
- Similarity remains a heuristic over thresholded tags, without independent scouting or predictive validation. Missing, average, and insufficiently sampled behavior are not yet fully separated.
- The current era is useful for retrospective comparisons; do not reuse future-inclusive pools as historical as-of validation.
- The architecture documentation still says archetype modules are no longer on the portrait path, but the builder imports and calls starter/bullpen archetype helpers.
- Both READMEs still say 2.3 million pitches per season. Inspected full-season files contain roughly 0.70–0.74 million; 2020 is shorter. Player-season counts also need a stated policy for stints, side, and cameo rows.
- Operations examples for the season argument and full refresh stages were corrected. The fingerprint narrative still overstates implementation coverage and replay checks.
- The validation suite has expanded meaningfully, but the workflows still do not run an independent correctness suite on pull requests. Some checks replicate implementation logic: V8 repeats the same foul-tip classification, and V19 reconciles to the same event filter rather than an external official ledger. V18 tolerates fewer than five over-slack players; V20 skips absent files. Those checks have specific scopes, not broad guarantees.
- Dependency reproducibility is unchanged: broad minimum versions remain, including a pandas floor below the version needed for `include_groups=False`. The large portrait/chart modules and analytics helpers inside chart code still make changes harder to isolate.

## Suggested repair order

1. Correct speed units and add authoritative regression examples.
2. Make every publishing entry point fail before any write on incomplete/stale builds; constrain deletions to complete requested scopes.
3. Make provenance distinguish feature recomputation from trait replay.
4. Correct shared pitch outcomes, sequence adjacency, league-wide attempt ranks, and Compare side keys.
5. Replace/relabel service time and the remaining misleading proxies; repair or retire unused projection/battery outputs.
6. Rebuild and verify the entire affected snapshot, freeze matching era roots, and only then publish. Add the failing cases above to pull-request checks before undertaking larger refactors.
